# 微软积分自动任务脚本

在后台自动完成 Microsoft Rewards 任务，完成后推送汇总。

## 授权（首次必做）

1. 自动授权:
   - 手动运行一次，等待一分钟
   - 查看token状态
   - 有token就无需其它操作
   - 无token则**手动授权**

2. **🔑 手动授权**，在打开的微软页面登录账号。(有两种方法)
   - *方案1*：点击手动授权(看准时机复制地址栏内容，地址栏会发生变化)，授权码必须包含(code=M.xxx=2052):
   - *方案2*：手动授权→F12→网络(Network)→oauth20_desktop.srf?removed=true →标头(Headers)→请求标头(Request headers)→Referer→复制右侧完整链接
     
      <img src="https://scriptcat.org/api/v2/resource/image/fZBP77hgN0mgSZl6" alt="img" style="width: 400px; height: auto;">
   
   - **📋 粘贴授权码**，把整段地址粘进去，回车。
   - 提示"授权成功"即可。之后用 Token 运行。

**授权码长什么样**：地址里包含 `code=M.xxx=2052` 的链接，形如

```
https://login.live.com/oauth20_desktop.srf?code=M.C561_BAY.2.U.MsaArtifacts.xxxxx&lc=2052
```


> 授权码**只能用一次**。若提示"换取 Token 失败"，多半是码已过期或被用过，重新走一遍上面的步骤。状态可用菜单 **📊 Token状态** 查看。

## Edge / Chrome 都能完成（1.3.1 起）

**不存在「必须在 Chrome 才能完成的任务」**，也不需要降级 Edge 或装 MV2 扩展。

### 真正的原因

必应的交卷 / 领取接口只接受 `Origin: https://rewards.bing.com`：

| 发送方 | Origin | 结果 |
| --- | --- | --- |
| rewards 页面里的 `fetch` | `https://rewards.bing.com` | **200 记账** ✅ |
| 扩展后台 / offscreen document | `chrome-extension://<id>` | 500 风控页 ❌ |

实测：同一份 MV3 扩展在 **Chrome 里从后台发也一样 500**。所以问题从来不是浏览器品牌。

### 解决办法：CDP 同源通道

脚本保持 `@background`（**后台常驻，关掉所有页面也会按 20 分钟一轮自动跑**），
同时通过调试端口在真实页面里发请求。

**一次性配置**（详见 `Rewards-Edge-CDP.ps1`）：

```powershell
powershell -ExecutionPolicy Bypass -File Rewards-Edge-CDP.ps1
```

它会：
1. 建一个独立配置目录 `%LOCALAPPDATA%\Microsoft\Edge\CDPUserData`（约 200KB，不影响日常 Edge）
2. 从 `Profile 6` 复制登录态（Cookies + Local State + Preferences）
3. 以 `--remote-debugging-port=9224` 启动 Edge 并打开 rewards 页

之后**保持这个窗口开着**即可，无需重复登录。

### 怎么确认生效

脚本日志里应出现：

```
CDP 调试端口 9224：✅ 可连
🖥️   经由 CDP 页面通道交卷成功
```

### 通道优先级

```
local（脚本被注入 rewards 页时）→ page（CDP）→ proxy → xhr（仅兜底）
```

| 任务 | 状态 |
| --- | --- |
| 带锁 🔒 卡片(已解锁) | ✅ |
| 桌面端任务（每周专属） | ✅ 1.4.1 起改为真实检测 |
| 首页待领取 | ✅ |
| 月度打卡 | ✅ 1.3.1 起 |

## 桌面 / 月度打卡：为什么必须「真实检测」（1.4.1）

1.3.1 的日志写着「本次完成 1 张」，实际一分没进账。原因有两层：

1. **服务端只把「未完成」的子卡写进 RSC payload。**
   已完成的子卡连 `offerId`/`hash` 都不下发。
   旧代码解析到 0 张卡就当成「本周已全部完成」上报 —— 日志漂亮，进度没动。
2. **旧代码还把 CTA 按钮上的 `M6.25 4.5A1.75`（外链箭头）当成「锁图标」**，
   于是所有带按钮的卡都被判成锁定，真正该做的卡反而被跳过。

1.4.1 改成的判定方式（全部实测过，探针脚本在 `_probe/`）：

| 判据 | 来源 |
| --- | --- |
| 进度 `N/M` | 页面顶部「状态: N/M 个任务」计数器（权威） |
| 已完成 | 该行状态图标带 `bg-statusSuccessRewardsBg`（里面是对勾） |
| 显示锁定 | 行内显式 `"isLocked":true`，或图标是空圈 `border-ctrlChoiceBaseStrokeRest` |
| 可交卷 | 服务端下发了 `offerId` + `hash`（**与是否显示锁定无关**） |

并且：

- **`全部完成` 只在 `N>=M` 且每行都有对勾时才算**；读不到计数器一律不下结论。
- 交卷后必须看到**计数器真的 +1**（或该行变成对勾）才算 `confirmed`，
  只是「响应 200/`1:true`」不够 —— 否则就报「已受理但没记账」。
- 不再按星期/锁定决定「要不要做」：只要服务端给了 `hash` 就去尝试，
  页面显示锁定也照样走一遍，成不成由交卷后的进度复核裁决。

### 只交卷就够了，不需要开标签（1.4.2）

`punchcard` 子卡和首页待领取都是 `urlreward`，记账通路就是 **CDP 页面里同源交卷**：

```
CDP 页面通道：在已开着的 rewards 页里 fetch POST（Origin 同源）→ 服务端 1:true → 记账
```

曾经试过「先导航到目标页 → 在 bing 页里上报 /rewardsapp/* → 再回来交卷」，
实测结论是**对是否记账没有帮助**，只会让浏览器来回跳页、多开标签：

| 做法 | 结果 |
| --- | --- |
| 直接交卷（已解锁卡） | `1:true`，进度 0/5 → 1/5，**真记账** |
| 访问 + 上报 + 交卷（已解锁卡） | 同样记账，没有更快也没有更稳 |
| 访问 + 上报 + 交卷（显示锁定卡） | 全是 200，进度**不动**（服务端不给记） |

所以 1.4.2 起：
- **移除**了「导航到 bing 页 + 应用搜索上报」这一整套，脚本不再自动开标签；
- `_ensurePageChannel` 直接返回 null（只借用已开着的 rewards 页，不再新开）；
- `earnPage()` 删掉「允许新开标签」的分支。

> `/rewardsapp/*` 是 bing.com 自己的接口：在 bing 页里发是 200，
> 在 rewards.bing.com 里发跨域抛异常（恒 -1），扩展后台直发也会被拒。
> 这条知识保留在 `reportAppSearchForCard` 的注释里，留给首页「等级门槛卡」用，
> 但它现在只做后台直发的尽力尝试，**不会再动你的标签页**。

> 注意：`WW_pcparent_FY27_Duolingo3M_punchcard` 这类入口有时是空壳
> （页面里既没卡片也没有计数器），现在会如实记「当前没有活动面板」，
> 不会写成「已完成」。

## 通知：只在「其它都做完了」时推一条（1.5.0）

以前每轮（20 分钟）都会推一份明细，签到/阅读/Edge 连签各自还会单独弹一条。现在**逐项播报全部取消，只在收尾统一推一条结论**。

判定在每轮结束时做（`RewardsAuto._notifyDailyDigest`）：

| 情况 | 结果 |
| --- | --- |
| 核心任务（签到 / 阅读 / PC 搜索 / 活动卡片 / 每日活动 / Edge 连签）还有没做完的 | **不推送**，明细只写日志 |
| 核心全做完，且桌面 / 锁卡 / 待领取也都了结 | 推「🎉 今日任务已全部完成」 |
| 核心全做完，只有下面三类没做完 | 推「✅ 其它任务已全部完成，还剩 N 项」，并说明每类剩多少 |

允许留空但要说清的三类：

- **🖥️ 桌面专属任务**——列出还剩哪几张（含「未到解锁日」标记），读不到状态时如实写「N 个入口读不到状态」；
- **🔒 带锁的日常任务**——只写张数与分值（1.5.1 起不再列卡片名、也不再附「需在必应 App 内完成」）；
- **🎁 首页待领取**——写清是「通道未受理 / 冷却中 / 待复核 / 状态读不出来」。

其它约束：

- 同一天同样的结论只推一次（`Config.digestKey` 按「日期 + 结论」去重），每天最多 4 条；
- 判断「没做完」用的状态里，`连续 N 次`、`冷却 N 分钟` 这类会变的措辞已归一化，否则每轮都会被当成新状态重推；
- 「全部完成」那条会顺带交代桌面任务和待领取的状态，避免看着 6 项都 ✅ 却以为漏了别的。
- 1.5.1：带锁的日常任务那行简化为 `🔒 带锁的日常任务 · ⏳ 3 张（30 分）`，不再列卡片名，也不再附「需在必应 App 内完成」（要看是哪几张，日志里有）。
- 1.5.2：遗留项下面追加一行 `💡 这几项要自动完成：用 Chrome 跑脚本，或配好 CDP 通道`。这三类都得靠浏览器级通道才能记账（锁卡要真实点击、待领取要走同源 server action），普通扩展后台做不到。全部完成时不出现这行。
- 1.5.3：该提示行去掉括号补充（原本还带「当前 Edge xxx 会被服务端拒」「Rewards Edge 快捷方式 · 端口 9224」），端口等细节看诊断面板。

## 什么时候停止今天的检测（1.6.0）

历史行为：关掉「持续检测」时，核心任务一做完成就立刻收工，那三项一次都不再试；开着「持续检测」时又永远不停，整天每 20 分钟空跑。

现在按「核心必完成、三项给缓冲」来判定（`RewardsAuto._settleToday`）：

| 情况 | 结果 |
| --- | --- |
| 核心任务还有没做完的 | 不停，交给调度跑下一轮 |
| 核心全完成，三项也了结 | 关「持续检测」→ 立即收工；开着 → 继续（保持原语义） |
| 核心全完成，三项还剩 | **再试 3 轮**（约 1 小时），仍是遗留 → 今天收工，明天自动恢复 |

细节：

- 三项 = 桌面专属任务 / 带锁的日常任务 / 首页待领取。它们本来就是「没配 CDP 就永远做不了」的任务，一直轮询只是空跑。
- 轮数记在 `Config.softSettleRounds`（按日期存，跨天归零，浏览器重启不丢）；`Config.softLast` 记上一轮还剩几项，所以重启后「三项已了结」能直接收工，不会白跑一轮。
- 这种「先收工」在没有全部完成时也会停 —— 靠 `Config.doneReason = soft` 区分：开着「持续检测」时，只有它能让调度停下来；真正的全部完成仍按开关走。
- 收工日志为 `💤 三项还剩 N 项没做完（已连试 3 轮），今天先收工，明天自动恢复`，只写日志不推送（每天那条结论已经在收尾播报里发过了）。

## 通知策略：只推「结果」，不推「环境」（1.4.4）

推送通道（浏览器通知 / Webhook）只留给**需要你立刻处理的事**：授权、搜索受限、以及 1.5.0 起的那一条收尾结论。
签到、阅读、Edge 连签、领取成功这类「中间结果」全部降为只写日志，不再单独弹。

「环境没配好」这一类固定信息一律只写日志（`Utils.logQuiet`），不再弹通知：

| 场景 | 1.4.3 及以前 | 1.4.4 |
| --- | --- | --- |
| CDP 未连接 / 端口 9224 没有调试服务 | 系统通知（旧版），且带整段启用命令 | 只写日志 |
| 应用内搜索型卡因无 CDP 跳过 | 日志 | 只写日志 |
| 待领积分三种通道全 0✗/500✗ | 每轮一条通知 | 只写日志（判据见 `_calmClaimFailure`） |
| Cookie 缺 Bing 登录标识 | 每轮一条通知 | 只写日志 |
| 桌面专属任务入口读取失败 / Token 失败 | 每轮一条通知 | 6 小时最多一条 |

只有服务端**真的拒绝**（401/403/404/405 等业务响应）才算「结果」，这时才推通知，并且同类提示 6 小时内只推一次。

## 待领积分通知不再刷屏（1.4.3）

1.4.2 及以前有两个毛病：

1. **把空池当成有分**。`pointClaim` 只要不是 `null` 就判「有分可领」，
   但空池也会留一个 `{}`／`[]`／`{"points":0}`，于是每轮都去领、每轮都失败。
2. **失败提示没有节流**。常驻调度 20 分钟一轮，同一条「三种通道都没受理」一天能推几十条。

1.4.3 的判定（`ClaimPoints.parse`）：

| 页面里读到的 `pointClaim` | 结论 |
| --- | --- |
| `null` / `[]` / `{}` / 明确 0 分 | 空池，直接记「无可领」，**不请求、不通知** |
| 读到 `>0` 的数字 | 确有可领，才去走通道 |
| 对象里读不出数字 | 状态未知，本轮跳过，只写日志、不通知 |

另外：

- **同类失败 6 小时只推一次**（`Utils.notifyKeyed`，浏览器通知和 Webhook 一起压）；
- 连续 2 次不受理后**冷却 90 分钟**再试，不再每轮去撞风控；
- 待领池的页面读取改为 `cache: "reload"`，避免命中缓存把「已领完」读成「还有分」。
